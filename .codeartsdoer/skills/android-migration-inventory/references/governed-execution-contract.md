# Governed execution contract

- `input_files: file-backed fixture`: frozen Android source/APK, Phase 1 scope and gate report, Phase 2 work order, Android CLI configuration, environments, accounts, and seed-data readiness.
- `owner`: Android-Harmony Migration Maintainers.
- `review cadence`: every release and after scanner, evidence, page-gate, advanced-probe, or inventory-schema changes.
- `output contract`: complete static and runtime-correlated catalogs for every included feature/page/state/environment, immutable evidence packages and controller anchors, deterministic page/advanced gate reports, and exact Phase 2 `PASS`; otherwise a blocking backlog with no invented coverage.
- `rollback boundary`: do not mutate frozen source, evidence, anchors, or accepted catalog history. Repair scanners in version control and create new evidence IDs or superseding records.

## Claim boundary

Static candidates are hypotheses, runtime observations are bindings, and only deterministic scripts grant `PAGE_PASS` or Phase 2 `PASS`. Model confidence, prose summaries, screenshots without hashes, and worker actor strings cannot close coverage. Provider telemetry, authenticated CodeArts identity, special production accounts, and unreachable runtime states stay `missing evidence` until captured.

## Routing boundary

Own Android discovery and semantic inventory only. Do not create HarmonyOS scaffold files, implement ArkUI behavior, or claim end-to-end migration completion.
