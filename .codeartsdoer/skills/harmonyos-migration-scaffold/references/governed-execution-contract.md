# Governed execution contract

- `input_files: file-backed fixture`: canonical Phase 2 closure, inventories, evidence anchors, advanced obligations, asset package, Phase 3 work order, bundled ArkUI Stage template, and frozen Harmony toolchain configuration.
- `owner`: Android-Harmony Migration Maintainers.
- `review cadence`: every release and after template, project mapping, command-contract, screenshot, or Stage 3 gate changes.
- `output contract`: buildable/installable/launchable template-derived HarmonyOS project with real route or surface shells, public UI foundations, interface-only capability contracts, locked asset landing plans, sealed HENV/HVER evidence, and exact Gate 3 `PASS`; no business behavior.
- `rollback boundary`: never alter Phase 2 input or a sealed HENV/HVER. Revert package-source changes through version control and issue new environment, verification, work-order, or rework IDs.

## Claim boundary

Successful project generation proves only the scaffold. It does not prove business parity. A fake CLI, manually supplied screenshot, prose-only route, or self-declared command result cannot pass. Governance scorecards never replace the canonical Stage 3 validator or controller Gate 3.

## Routing boundary

Own architecture and non-business landing points only. Send Android coverage gaps back to Phase 2 and business/UI parity implementation forward to Phase 4 under a controller work order.
