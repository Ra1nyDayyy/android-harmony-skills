# 四阶段人在回路迁移系统设计

## 目标

保留四个迁移 Skill 和现有确定性验证脚本，把系统改成“机器完成全量检查，人工只做阶段决策”。模型可以提交结果、报告阻塞或建议返工，但不能签发 `PASS`、`APPROVED` 或“迁移完成”。

## 统一状态机

每个阶段依次经过：`RUNNING -> AUTO_GATE_PASS|AUTO_GATE_FAIL|BLOCKED -> WAITING_HUMAN_REVIEW -> APPROVED|REWORK|APPROVED_DEVIATION|MANUAL_TAKEOVER`。只有机器门禁为 `AUTO_GATE_PASS` 且存在绑定当前门禁报告哈希的 `APPROVED`，控制器才能签发下一阶段工单。人工偏差不能改写机器差异，也不能把机器失败变成通过。

## 四阶段职责

- Phase 1：冻结源码、APK、范围、环境和账号；人工审核范围与前置条件。
- Phase 2：自动发现并验证 Android 页面、状态、组件、跳转、业务规则、动态风险和副作用；人工审核页面地图、未覆盖项和低置信项，不在阶段内部手工补表。
- Phase 3：从内置模板生成可构建、可安装、可启动的非业务基座，建立每个 Page-ID 的路由和载体落点；人工审核结构、路由、载体类型和缺失资源。
- Phase 4：一个 Page-ID 一个页面工单，共享能力使用独立 Capability-ID 工单；页面只能消费冻结的 Phase 2 合同。机器执行 Inspector、截图、几何、行为、跳转和副作用比较；人工审核差异摘要和关键样本。

## 人工审核包

每阶段输出统一 `review-summary.json`，只包含决策所需摘要：阶段、机器状态、覆盖率、严重/警告数量、最高风险、偏差、关键样本、证据链接和建议动作。UI 默认展示红黄异常与关键页面，绿色结果批量展示并允许抽样展开。原始 CSV、JSON、日志和截图仍保留，但不作为默认审核界面。

## 事实与幻觉边界

正式事实必须绑定源码位置、正式 Evidence-ID 或确定性工具结果。没有证据的模型推断只能是 `PENDING_CONFIRMATION`，并阻止相关迁移单元关闭。目标平台 API 必须通过冻结 SDK 检查、真实编译和模拟器运行，模型描述不构成可用性证据。

## 返工路由

人工退回或机器失败生成规范化问题记录。Android 事实错误退回 Phase 2；路由、载体或基座错误退回 Phase 3；页面实现错误退回对应 Page-ID；共享能力错误退回 Capability-ID。自动修复最多两次，之后进入 `MANUAL_TAKEOVER`。人工修改后必须重新走相同机器门禁与人工审核。

## Skill 复杂度边界

每个 `SKILL.md` 只保留触发范围、输入、单一执行入口、输出、机器门禁、人工门禁和失败路由。字段校验、哈希、状态机、PASS 计算和命令参数放入脚本/Schema；长领域说明放入最多四个按需 references；公共治理规则由 controller 协议统一定义。
