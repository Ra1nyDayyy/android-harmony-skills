# Phase 4 按页面负责的确定性一致性迁移设计

## 目标

重写 `harmonyos-feature-implementation` 及控制器的 Phase 4 接口，使 Phase 4 不再由一个 Agent 批量生成整个应用，也不再允许模型根据鸿蒙现状反向填写验收标准。

Phase 4 必须满足以下结果：

- Phase 2 的冻结交付物是 UI、功能、状态、跳转、资源和副作用的唯一事实来源。
- 每个 Phase 2 `Page-ID` 对应一份独立页面工单、一个固定页面负责人和一个真实 CodeArts 任务。
- 跨页面共享的计算、数据库、设置、路由和系统能力由独立公共能力工单实现，页面不得复制占位实现。
- 页面负责人不得验收自己的页面；模型无权签发机器 `PASS`。
- 真实 ArkUI `UIContext` Inspector、模拟器截图、功能断言和副作用证据共同参与确定性比较。
- 每个迁移单元最多一次初始验证和两次自动修复。预算耗尽后结果只能是 `REVIEW_REQUIRED`。
- 删除 `PASS_WITH_GAPS`、`PARTIAL`、`CAN_PROCEED` 和“后续再注入”等放行路径。

## 范围

本次重写覆盖：

- Phase 4 阶段工单和页面/公共能力子工单；
- Phase 2 到 Phase 4 的只读验收合同；
- 页面代码所有权和真实 CodeArts 执行回执；
- ArkUI Inspector 测试接入与证据采集；
- 组件、几何、截图、行为和副作用比较；
- 页面级返工、人工审核队列和最终 Gate 4；
- 原有 Phase 4 单元测试、工作流测试和回归夹具。

不扩展到 Phase 5 全应用系统回归或 Phase 6 发布交付。Phase 4 末尾只执行为证明页面间一致性所必需的集成回归。

## 权威输入

Phase 4 只能从通过 Gate 2 并被 Phase 3/控制器继续绑定的冻结文件构建验收合同。至少包括：

- 页面、组件、事件、跳转和状态目录；
- Android 运行截图、布局树、操作轨迹和环境；
- 功能输入、预期输出、业务规则和数据依赖；
- 数据库、剪贴板、网络、后台任务、振动和权限等副作用；
- Android 源码、资源、资产包和来源引用；
- Phase 3 已接受的模块、路由、页面载体和公共能力接口。

Phase 4 不得新增、删除或改写 Android 预期。发现缺失、矛盾或无法唯一解释的事实时，当前页面进入 `UPSTREAM_BLOCKED`，由控制器退回 Phase 2 或 Phase 3。不得让页面 Agent 猜测。

## 分工模型

### Phase 4 总负责人

总负责人只负责拆单、依赖、代码所有权、进度和返工路由，不直接实现页面或签发验收结论。

总负责人必须：

1. 枚举所有纳入范围的 `Page-ID`，不得按功能名称合并页面。
2. 为每个页面签发一份不可覆盖的页面工单。
3. 为跨页面公共能力签发独立能力工单。
4. 记录页面与公共能力之间的依赖。
5. 确保每份工单绑定不同的真实 CodeArts 任务 ID 和产物哈希。

### 页面负责人

一个页面工单只绑定一个固定页面负责人。该负责人对页面的全部状态负责，包括默认、空、加载、错误、禁用、按下、聚焦、弹窗和其他 Phase 2 已登记状态。

不同 `Page-ID` 必须绑定不同的页面负责人 ID 和不同的真实 CodeArts 任务 ID。任务可以受并发额度限制而排队执行，但不得因为并发额度不足而把多个页面合并给同一个页面负责人。

页面负责人负责：

- Android 组件到 ArkUI 组件的逐项映射；
- 页面 UI、页面内状态和交互；
- 调用已冻结的公共能力接口；
- 根据机器差异报告修复该页面；
- 在两轮返工中保持同一负责人和上下文。

页面负责人不得：

- 把 Page 改成 Dialog、Sheet、Popup，或反向替换；
- 增加 Android 不存在的标题栏、底部导航、按钮或装饰；
- 删除、合并或替换 Android 组件和功能；
- 直接修改其他页面的独占代码路径；
- 复制公共能力的假实现、固定返回或内存占位版本；
- 修改验收合同或比较结果。

Dialog、Popup、Widget 等只要在 Phase 2 中拥有独立 `Page-ID`，就按独立页面工单处理。

### 公共能力负责人

跨页面共享的能力按能力类型拆单，例如计算引擎、数据库、设置持久化、路由、剪贴板、振动和 Widget 服务。公共能力负责人只能修改工单冻结的共享代码路径，并提交可执行的确定性测试。

页面负责人通过接口调用公共能力。多个页面不得分别实现同一能力。

### 独立验证执行者

验证执行者与总负责人、页面负责人、公共能力负责人互异。其职责是执行冻结命令、采集证据并运行比较器，不得修改业务代码、Android 合同或比较阈值。

### 人工审核者

人工审核只处理两次自动修复后仍未通过的差异。人工可以批准明确的平台例外，但不能重写机器比较结果。例外必须形成独立、限范围、可追溯的批准文件。

## 工作单元

### 页面工单

每份页面工单至少绑定：

- `Page-ID`、全部 `State-ID` 和相关 `Feature-ID`；
- 页面载体类型；
- 页面进入与退出跳转；
- Android 验收合同哈希；
- Phase 3 目标模块、路由和载体哈希；
- 页面独占代码路径；
- 页面负责人和真实 CodeArts 任务 ID；
- 依赖的公共能力工单；
- 所有必须返回的代码、映射、测试和证据。

一个页面包含多个状态时仍由同一页面负责人完成，不把默认态和错误态分给不同 Agent。

### 公共能力工单

公共能力工单至少绑定：

- 能力 ID 和依赖它的所有页面；
- Phase 2 业务规则、输入输出和副作用合同；
- Phase 3 接口；
- 独占共享代码路径；
- 确定性单元/集成测试；
- 能力负责人和真实 CodeArts 任务 ID。

## Android 验收合同

新增机器生成的页面验收合同。每个迁移单元定义为：

`Page-ID × State-ID × Android-Environment × Harmony-Environment`

合同至少包含：

- 页面载体、父子层级和可见组件全集；
- 每个组件的来源 ID、类型、文本、资源、状态和可操作性；
- 组件在 Android 内容区域中的归一化坐标和尺寸；
- Android 截图、布局树和原始证据哈希；
- 页面进入步骤和前置数据；
- 事件、操作轨迹、跳转目标和操作后状态；
- 确定性业务断言及预期值；
- 数据与系统副作用；
- 可排除的系统托管区域及理由；
- Android 源码和资源引用。

合同由脚本从 Phase 2 工件计算，写入 Phase 4 只读输入并纳入控制器哈希链。不得接受页面 Agent、验证 Agent 或大模型生成的 `expected` 字段。

## 实现流程

1. 总负责人验证 Gate 3 和 Phase 2/3 输入哈希。
2. 生成全部 Android 页面验收合同和页面依赖图。
3. 签发所有页面工单和必要的公共能力工单。
4. 公共能力与不依赖它的页面可以并行；有依赖的页面等待能力测试通过后再接入。
5. 页面负责人先完成逐组件映射，再实现代码。映射不完整时不得进入验证。
6. 验证执行者构建、安装、导航、操作、截图和采集 Inspector 原始树。
7. 确定性比较器生成结构、几何、视觉、行为和副作用差异。
8. 全部比较通过时，当前迁移单元为 `PASS`。
9. 比较失败且仍有预算时，系统向原页面负责人或公共能力负责人开出规范化返工单。
10. 两次自动修复后仍失败时，迁移单元为 `REVIEW_REQUIRED`，Gate 4 保持关闭。
11. 所有页面单元通过或获得有效人工例外后，执行页面间集成回归。
12. 控制器独立重算所有输入、执行回执、证据、比较、返工和例外哈希，再决定 Gate 4。

## 真实 ArkUI Inspector 接入

当前只复制 Bridge 文件、依赖外部命令自行生成 JSON 的方式不够。重写后必须提供仓库管理的测试接入和执行适配器：

1. 将 Inspector Bridge 和测试入口安装到目标项目 `ohosTest`，不得进入发布模块。
2. 构建并安装目标 HAP 与测试 HAP。
3. 在冻结设备上进入目标页面并等待稳定。
4. 从当前窗口取得 `UIContext`，调用 `getFilteredInspectorTree()` 或按 ID 调用子树接口。
5. 输出原始树，不允许适配器自行生成归一化节点或 Android 绑定。
6. 拉取原始结果、设备日志和测试日志。
7. 仓库脚本重新计算原始树哈希、节点、几何和 Android 组件绑定。

每次采集绑定随机 `Capture-ID`、设备序列号、Bundle、Ability、页面、窗口、目标 HAP、测试 HAP、Hvigor/HDC 可执行文件和命令日志。普通 `uitest dumpLayout` 可以作为辅助证据，但不能替代正式 Inspector 原始树。

## 确定性比较

### 无条件阻断项

以下任一差异直接失败，不设视觉容差：

- 页面载体不同；
- 必需页面、状态、组件、事件或跳转缺失；
- 增加改变信息架构或交互的组件；
- 可操作组件类型或语义不同；
- 必需文本、图标、资源或状态错误；
- 业务实际值不满足 Phase 2 预期；
- 数据、持久化、权限或系统副作用不一致；
- 仍存在占位、固定返回、假数据、空适配器或未连接分支；
- 缺少真实 Inspector、截图、操作轨迹或命令证据。

### 几何比较

先扣除双方明确登记的系统托管区域，再把组件坐标映射到各自内容区域。默认自动通过阈值为：

- 单边位置或尺寸差不超过 `2dp`；并且
- 归一化差不超过内容区对应维度的 `0.5%`。

任一条件超出即进入返工。阈值来自环境配置，页面 Agent不得修改。

### 截图比较

截图比较只在相同页面状态、内容、主题、语言、方向和字体缩放下进行。流程包括画布对齐、最小系统区域遮罩、逐元素区域比较、全页面差异图和叠加图。

自动 `PASS` 的默认条件为：

- 应用控制区域 SSIM 不低于 `0.98`；
- 超过颜色差阈值的像素不高于应用控制区域的 `2%`；
- 任一必需组件区域不得出现空白、替代图标或明显形状差异。

这些数值允许轻微字体栅格和平台渲染差异，但不允许布局重做。超过阈值进入返工；不能由模型解释后自动放行。

### 行为和副作用比较

每条 Phase 2 事件必须在鸿蒙侧执行同一用户意图，并比较：

- 操作前状态；
- 操作对象和操作类型；
- 操作后页面、组件值和跳转目标；
- 业务输出；
- 数据库、设置、剪贴板、网络、权限、振动或后台任务结果。

例如 Android 的 `5+3=` 预期结果为 `8` 时，鸿蒙结果为 `0` 必须失败；“按钮可以点击”不能替代结果断言。

## 证据结构

每次迁移单元验证生成不可覆盖目录：

```text
evidence/<Migration-Unit-ID>/<Attempt-ID>/
├─ android-contract.json
├─ harmony-screenshot.png
├─ arkui-inspector-raw.json
├─ arkui-inspector-normalized.json
├─ assertions.json
├─ operation-traces.json
├─ side-effects.json
├─ command-logs/
├─ metadata.json
├─ manifest.sha256
└─ COMMITTED
```

比较结果单独保存：

```text
comparisons/<Migration-Unit-ID>/<Attempt-ID>/
├─ structural-diff.json
├─ geometry-diff.json
├─ pixel-diff.json
├─ behavior-diff.json
├─ overlay.png
├─ diff.png
├─ verdict.json
├─ manifest.sha256
└─ COMMITTED
```

`verdict.json` 只能由比较脚本创建。任何手写、提前存在或哈希不一致的结果均无效。

## 返工与人工审核

迁移单元状态只允许：

- `NOT_STARTED`
- `IMPLEMENTING`
- `VERIFYING`
- `REWORK_1`
- `REWORK_2`
- `PASS`
- `UPSTREAM_BLOCKED`
- `REVIEW_REQUIRED`

返工单包含具体页面、状态、组件、差异属性、Android 值、鸿蒙值、证据路径、责任工单和完成条件。相同页面的返工始终回到原页面负责人；公共能力缺陷路由给能力负责人，并标出所有受影响页面。

人工例外保存在独立目录，至少包含差异对象、双方值、无法保持一致的理由、影响范围、证据、审核身份和签署时间。例外不能覆盖机器差异报告，只能在 Gate 4 汇总时豁免其明确列出的比较项。

## 页面间集成回归

页面级通过后执行最小全应用链路，检查：

- 每个页面都能从冻结入口进入并正确返回；
- Dialog、Popup 和 Sheet 的打开、遮罩、关闭与恢复；
- 跨页面共享数据和设置立即同步；
- 计算、历史、复制、设置、重启恢复等端到端链路；
- 页面工单与公共能力工单的代码所有权无冲突；
- 所有页面通过时使用的是同一个最终构建和同一源码快照。

任何集成失败都重新打开关联页面或公共能力返工，不能因为单页曾经 PASS 而忽略。

## Gate 4

Gate 4 只接受：

- `PASS`：全部迁移单元和页面间集成回归通过，或存在完整且有效的人工例外；
- `FAIL`：存在仍可自动修复的失败；
- `REVIEW_REQUIRED`：至少一个单元耗尽自动修复预算或等待人工例外。

控制器必须独立验证：

- Page-ID 工单全集与 Phase 2 页面全集相等；
- 每份页面/能力工单有真实且互不冒充的 CodeArts 执行回执；
- Phase 2/3 输入和 Android 合同未改变；
- 页面代码所有权、公共能力依赖和最终源码快照一致；
- Inspector、截图、功能、副作用、比较和返工证据完整；
- 没有 `PASS_WITH_GAPS`、占位逻辑、未执行页面或模型自报 PASS；
- 所有最终证据来自同一最终构建。

## 失败处理

- 工具链或模拟器不可用：保留证据，当前单元为 `UPSTREAM_BLOCKED`，不得生成替代 PASS。
- Inspector 测试无法构建或运行：验证失败，修复测试接入；不得回退到手写 JSON。
- Phase 2 信息不足：退回 Phase 2 补证，并签发新的上游版本；不得修改旧合同。
- 页面间代码冲突：由总负责人重新划分独占路径或签发共享能力工单，保留旧工单历史。
- 比较脚本异常：当前比较无结论，不能按通过处理。

## 测试策略

### 单元测试

- Android 合同只能由 Phase 2 冻结数据计算；
- 页面全集与页面工单全集闭合；
- 页面 Agent 无法修改其他页面或共享能力路径；
- Inspector 原始树哈希、来源、API 和测试包绑定；
- 组件缺失、载体替换、错误 expected 和手写 PASS 被拒绝；
- 几何与截图阈值的边界用例；
- 真实业务结果与副作用断言；
- 三次执行预算和删除证据后不可重置；
- 人工例外只能豁免精确列出的差异。

### 工作流测试

使用小型多页面夹具验证：

1. 多个页面工单可以并行，但独占路径不冲突；
2. 公共计算能力只实现一次并被多个页面调用；
3. 页面改成 Dialog、删除组件、增加底部导航时 Gate 失败；
4. `5+3=0`、历史未保存和设置未持久化时 Gate 失败；
5. 一次初始失败、两次返工后进入 `REVIEW_REQUIRED`；
6. 全部页面通过但跨页面链路失败时 Gate 仍关闭；
7. 只有同一最终构建下的页面证据能打开 Gate 4。

离线测试可以使用明确标记的夹具执行程序，但正式迁移配置必须拒绝测试目录、fake CLI 和夹具开关。

## 兼容与迁移

现有 Phase 4 工单、`parity-map.csv` 和证据目录不原地升级为 PASS。旧运行若需要继续，必须签发新的 Phase 4 工作单版本并重新生成页面工单、验收合同和真实证据。

保留现有 Phase 1–3 的冻结工件和 Gate 语义。Phase 4 重写只增加更严格的输入闭包，不修改已经封存的旧证据。

## 完成标准

只有同时满足以下条件，Phase 4 重写才算完成：

- 每个 Phase 2 页面均由独立页面工单和固定负责人覆盖；
- 公共能力无重复占位实现；
- Inspector Bridge 被真实安装到 `ohosTest` 并由仓库适配器执行；
- 结构、几何、截图、行为和副作用比较均由机器生成；
- 两次返工预算和 `REVIEW_REQUIRED` 无法绕过；
- Gate 4 不再接受任何带缺口通过状态；
- 原有与新增测试全部通过；
- README、连续执行契约、角色规约和交付审计同步更新。
